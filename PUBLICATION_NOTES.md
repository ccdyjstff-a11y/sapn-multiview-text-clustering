# Publication preparation and historical paths

This is the reviewable research snapshot prepared for the authorized public distribution. Preparation is distinct from an actual upload: the publication workflow records the verified repository address and revision after successful publication. No DOI or additional open-source license is implied. RIGHTS.md records the distribution and reuse boundaries. The release contains research sources, their adaptation interfaces, derived results and public source metadata; external raw corpora, class vectors, full-text papers and third-party author optimizers are not bundled.

Historical manifests, protocol receipts and source mappings retain some absolute workstation paths, including a Windows account-directory component. They identify the original location of an input or execution artifact; they are not credentials, download addresses or usable paths on the reader's machine. The path-bearing records remain byte-identical where required by their historical hashes and compact-replay manifests. Editing those strings in place would invalidate the evidence bindings. The new English README and other derived explanatory documents use relative paths or generic example directories instead of personal workstation paths.

The English common solver's derivation record embeds its historical predecessor descriptor, so that descriptor also retains its original path metadata. Its current runnable source identity is bound separately. Synthetic verification receipts may preserve traceback locations from their executed refusal tests. Those are execution provenance, not requirements for running the release. The publication inventory lists every path-bearing file by relative release name and records why it is retained; it does not reproduce the personal directory components in the inventory itself.

Three active Python modules retain Chinese exception-message strings: `common/allocation_core.py`, `benchmark/sapn_text_paper.py` and `benchmark/sapn_text_research.py`. Every such string occurs within a `raise` expression. They are not comments, docstrings, identifiers or scientific result text. Keeping them preserves executable string constants and the documented token/AST equivalence. All active Python comments and docstrings, and the included own MATLAB worker comments, are English. Original `.py.txt` provenance copies intentionally retain their historical bytes and are not active entry points.

The packaging helper is maintained alongside this directory as `package_release.py`. Its default `audit` mode only writes an external inventory. Its explicit `build` mode first refreshes release QA and SHA256SUMS, re-audits the inventory, creates a deterministic local ZIP and a per-member manifest, then verifies every archived member. It never uploads files. Unknown secret-like values, raw feature/class payloads, full-text documents, unapproved MATLAB files or missing documented release assets block packaging. Historical path metadata is disclosed separately, not silently rewritten or advertised as anonymized.

The manifest and integrity checks describe a concrete snapshot. Adding extension, tie-stability or independent-reproduction results requires refreshing them. A compact evidence replay is not MATLAB retraining; the PCBG/SSA historical training path dependencies and separate author-code acquisition remain described in `baselines/README.md`.

The completed local snapshot includes the separately sealed two-corpus allocation extension and posthoc tie sensitivity. Tie source copies and the independently executed portability/compact-scoring receipts are hash-bound. Adapter planning, relocation and stored-state scoring are distinguished from actual new optimizer reproduction. All original raw inputs, class vectors and full optimizer states remain outside the compact release. Research-owned plot PDFs/SVGs/previews and QA overlays are individually hash-allowed; they are not manuscript full text or a blanket image/PDF inclusion rule.

The original local ZIP and its per-member manifest remain unchanged historical artifacts outside this directory. The initial v1.0.0 publication copy changed only distribution documentation and Git file-handling metadata; `provenance/PUBLICATION_PREPARATION.json` records those changes against the original local release. Its own `SHA256SUMS` binds the prepared files and excludes itself. Remote accessibility and the actual revision must be verified separately after upload. Historical paths remain disclosed in the content inventory; public hosting does not assign a DOI or an additional open-source license.
